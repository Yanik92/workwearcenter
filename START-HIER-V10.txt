WORKWEARCENTER (Yanik Textildruck) – VERSION 10.12.3
================================================

Dieses Paket ist beides:
  A) ein kumulatives UPDATE für die bestehende Installation (ab Version 8/9) und
  B) eine vollständige NEUINSTALLATION für einen neuen Server.
Eine produktive config.php ist absichtlich NICHT enthalten.

VORAUSSETZUNGEN
- PHP 8.1 oder neuer (getestet mit 8.4)
- MySQL 5.7+/8 oder MariaDB 10.4+ mit InnoDB und utf8mb4
- PHP-Erweiterungen: PDO MySQL, mbstring, fileinfo, OpenSSL, (empfohlen) curl
- HTTPS für workwearcenter.de

-------------------------------------------------------------------------------
A) UPDATE EINER BESTEHENDEN INSTALLATION
-------------------------------------------------------------------------------
1. Webspace, Datenbank und config.php vollständig sichern (und Download prüfen).
2. Inhalt des Ordners in das Stammverzeichnis hochladen, Programmdateien ersetzen.
   Versteckte Dateien mitnehmen: .htaccess, .user.ini, uploads/.htaccess,
   app/.htaccess, tests/.htaccess, tools/.htaccess
   config.php und den Ordner uploads NICHT überschreiben oder löschen.
   FileZilla: bei „Zieldatei existiert bereits“ immer „Überschreiben“ wählen
   (nicht „falls Quelle neuer“). Admin → Systemstatus → „Programmdateien
   vollständig hochgeladen“ zeigt danach, ob jede Datei angekommen ist.
3. Als Administrator anmelden → https://workwearcenter.de/update.php
   Sicherung bestätigen, Update einmal ausführen (legt die neuen Tabellen an).
   (Kommt das Update von einer Version vor 10.3: danach Admin → Inhalte →
   „Neue Texte übernehmen“ klicken; alte Texte werden gesichert.)
   NEU 10.10: uploads/.htaccess unbedingt mit hochladen (sperrt Listen/Exporte).
4. Admin → „Mein Konto“: Zwei-Faktor-Anmeldung einrichten, Codes sicher ablegen.
5. Admin → „Systemstatus“: alle Prüfungen durchgehen.
6. Admin → „Übergabe“: ältere freigegebene Aufträge ggf. „für Übergabe vorbereiten“.
   Die Verbindung zur Auftragsverwaltung wird eingeschaltet, sobald diese bereit ist
   (Anleitung: SCHNITTSTELLE-AUFTRAGSVERWALTUNG.md). Bis dahin wird gesammelt.

-------------------------------------------------------------------------------
B) NEUINSTALLATION
-------------------------------------------------------------------------------
1. Leere Datenbank beim Hoster anlegen.
2. Dateien hochladen, config.example.php kopieren und als config.php speichern,
   Datenbank- und Mailzugang sowie einen langen install_key eintragen.
3. https://ihre-domain/install.php öffnen, install_key und Admin-Daten eingeben.
   Der Assistent legt alle Tabellen an und sperrt sich danach selbst.
4. Weiter wie oben ab Schritt 4.

-------------------------------------------------------------------------------
WEBSERVER: SPERREN PRÜFEN (wichtig)
-------------------------------------------------------------------------------
Alle Sperren (Programmordner app/, Lieferantenpreise, Anleitungen, Uploads ohne
Skripte) stehen in .htaccess-Dateien. Das wirkt nur unter Apache mit
„AllowOverride All“. Admin → System → Systemstatus prüft das von außen
(„Interne Dateien gesperrt“) und muss grün sein.

Bei nginx (oder wenn die Prüfung rot ist) diese Regeln beim Hoster eintragen:

    location ~ /\.(?!well-known/)              { deny all; }
    location ~ ^/(app|tests|tools)/            { deny all; }
    location ~ ^/uploads/.*\.(php\d?|pht|phtml|phar|phps|s?html?|xhtml|xml|json|csv|xlsx?|zip|txt|sql)$ { deny all; }
    location ~ ^/uploads/.*\.svg$ {
        add_header Content-Security-Policy "default-src 'none'; style-src 'unsafe-inline'; sandbox" always;
        add_header X-Content-Type-Options "nosniff" always;
    }
    location ~ ^/(config\.php|config\.example\.php|cron\.php|install\.php|VERSION|[A-Z][A-Z0-9-]*\.txt)$ { deny all; }
    location ~ \.(md|ya?ml|sql|log|ini|bak|zip)$ { deny all; }
    location / { try_files $uri $uri/ /index.php?$query_string; }

(Die deny-Regeln müssen vor der PHP-Regel „location ~ \.php$“ des Hosters
stehen. install.php erst nach der Einrichtung sperren. Außerdem in der
PHP-Konfiguration: display_errors=Off, expose_php=Off.)

Am sichersten: in der config.php 'private_dir' auf einen Ordner AUSSERHALB des
Webroots setzen. Dort liegt dann die eingelesene Daiber-Liste mit Einkaufspreisen.

-------------------------------------------------------------------------------
CRONJOB (Pflicht für den Betrieb)
-------------------------------------------------------------------------------
cron.php alle fünf Minuten per PHP-CLI ausführen, z. B.:

    /usr/bin/php /VOLLSTAENDIGER/SERVERPFAD/cron.php

Er versendet E-Mails, überträgt Aufträge an die Auftragsverwaltung und löscht
abgelaufene Daten (Sicherheitsdaten, versendete Mails nach 90 Tagen, erledigte
Anfragen nach 24 Monaten). cron.php ist über den Browser gesperrt. Der Systemstatus zeigt, wann er zuletzt lief.

-------------------------------------------------------------------------------
LEXWARE OFFICE ANBINDEN (optional, ab 10.11)
-------------------------------------------------------------------------------
1. In Lexware Office als Benutzer anmelden, der Kontakte und Rechnungen anlegen
   darf (am besten der Inhaber/Administrator). Der Tarif muss Rechnungen
   enthalten, sonst antwortet Lexware mit „402“.
2. https://app.lexware.de/addons/public-api öffnen (Erweiterungen → Public API),
   Schlüssel erzeugen und kopieren. Der Schlüssel handelt mit den Rechten dieses
   Benutzers – wie ein Passwort behandeln, nie per E-Mail weitergeben.
3. In der config.php eintragen:   'lexware_api_key' => 'DER-SCHLÜSSEL',
   'lexware_api_base' bleibt 'https://api.lexware.io' (nur für Tests ändern).
4. Admin → System → Lexware Office → „Verbindung testen“. Dort auch Belegtitel,
   Einleitung und ob Bestellernamen in den Positionen stehen sollen.
5. Je Firma einmal den Kontakt anlegen oder einen vorhandenen verknüpfen.
Danach: Auf der Auftragsseite „Rechnungsentwurf erzeugen“ oder auf der
Lexware-Seite eine Monats-Sammelrechnung (optional je Kostenstelle). Es entstehen
NUR Entwürfe – prüfen, finalisieren und versenden immer in Lexware. Jeder Auftrag
kann nur einmal abgerechnet werden. Meldet Lexware eine Zeitüberschreitung, bleibt
der Auftrag gesperrt, bis unter „Rechnungsentwürfe → Klären“ entschieden ist.
Lexware nimmt höchstens 300 Positionen je Rechnung an: Größere Sammelrechnungen
teilt das System ab 10.15 automatisch in mehrere Entwürfe auf (ganze Kostenstellen,
sonst „Teil 1 von 3“), die Vorschau zeigt die Aufteilung vorher. Scheitert ein Teil,
bleibt er in der Monatsübersicht stehen und wird mit „Erneut senden“ nachgeholt.
Schlüssel widerrufen: in Lexware löschen und den Eintrag in der config.php leeren.

-------------------------------------------------------------------------------
VOR DEM ÖFFENTLICHEN START
-------------------------------------------------------------------------------
Vor dem Start mit einem Großkunden: GO-LIVE-CHECKLISTE.md abarbeiten. Siehe auch ABNAHME-CHECKLISTE-V10.md. Insbesondere Impressum (inkl. USt-IdNr.) und die
Datenschutzerklärung (Vorlage unter Admin → Inhalte → Datenschutz) fachlich prüfen.

ROLLBACK
Bei einem Fehler keine alten und neuen Einzeldateien mischen. Webspace UND
Datenbank aus derselben Sicherung gemeinsam wiederherstellen.
